## Почта команды — `messages/` (временная папка)

**Урок репетиции:** на прогоне 20.09 Виталий прислал 4 сообщения (правки к контракту, 6 багов движка, запрет менять форму action, пакет правил). Дмитрий не ответил ни на одно — ноль файлов от `dmitry`. Результат: баги не были починены, контракт изменён в одностороннем порядке, экран сломался.

**Правило:**
- Длинные сообщения друг другу кладём файлом в `messages/`, а не шлём в мессенджер. Одна папка на двоих, без деления по адресатам; автор указан в имени файла.
- Формат имени: `ГГГГ-ММ-ДД_ЧЧММ_автор_тема.md` (автор — `vitaly` или `dmitry`, только латиница и дефисы).
- Первая строка файла: кому и что нужно сделать, к какому часу.
- Чужие файлы не правим: ответ — новым файлом.
- **Отправка:** `git add messages`, коммит `час N (имя): сообщение <тема>`, `git pull --rebase --autostash`, `git push` (по просьбе человека это делает Codex). Сообщение — тоже работа часа, коммит считается.
- **Получатель** делает `git pull` и читает новые файлы. Новые файлы = новые задачи. Читать при каждом pull.
- **Ответ обязателен.** Даже коротко: «принял, пункты 1-4 до 15:40, 5-6 после». Без ответа другой не знает, что происходит.
- **Агенты (Codex, Claude) папку не пишут и не удаляют: сообщения пишет и читает человек.**
- **Папка временная.** По окончании работы капитан (Виталий) удаляет: `git rm -r messages`, коммит, push. В сдаваемом репозитории `messages/` быть не должно.

Подробный формат — `messages/README.md`.

## Git

**Урок репетиции (разбор 20.09, по истории репозитория):** за пять часов у Дмитрия было 4 отправленных коммита, у Виталия 57. Работа Дмитрия попала в GitHub двумя пачками (16:06 и 17:18), а всё остальное время лежала у него на ноутбуке. **Правила:**
- **Одна ветка `main`.** Отправка: `git pull --rebase --autostash`, потом `git push`.
- **Отправка каждые 10 минут, а не раз в час** — даже если задача не закончена. Коммит «промежуточный: работает расчёт склада, не работает прецедент» — нормальный коммит, он и есть доказательство прогресса (п. 6.6).
- **Коммит и push делает Codex сам**, без просьбы человека: после каждой принятой задачи (зелёный DoD) и всегда, если с последней отправки прошло больше 10 минут. Claude (Прораб) в git не пишет и не пушит: у него `push` закрыт. Коммитить в обход Codex нельзя.
- **:35 каждого часа.** Если в этом часу нет отправленного коммита — сделать его немедленно из того, что есть: код, тест, данные, схема, заметка. П. 6.6 принимает любой подтверждённый прогресс. Окно :40–:55 из старых правил отменено: нужен коммит **в любой момент часа**, но не позже :59.
- **Будильник на телефоне на :30 каждого часа.** Агент оживает только когда его запускают: не подходил час — сам не напомнит.
- **Формат коммита:** `час N (Дмитрий): что сделано` (при коммите наряда — `D-007: суть`, `час N` можно не писать: судья смотрит на время и автора).
- **Codex — внутренний выбор команды, не требование Положения.** П. 5.4.12 разрешает любые AI-инструменты и прямо говорит, что Codex не обязателен, если иное не установлено условиями конкретной задачи. Лимиты Codex контролируем по командному плану; вклад каждого участника должен быть подтверждаемым (п. 5.4.7).
- Ключи и `.env` в репозиторий не попадают; образец настроек — `.env.example`. Историю не переписываем: никакого `push --force`, `amend` уже отправленного.
- Работа только в этом репозитории.
- **Папки `server/` и `web/` разные → конфликтов при merge не бывает.** Дмитрий пушит `server/`, `contract/`, `docker-compose.yml`, `README.md`. Виталий — `web/`, `CASE.md`, `TASKS.md`.
