# Проверяемость решения для технического жюри

Официальные критерии: [задание](task/akim_task.md). Баллы 23/25 и 24/25, ранее названные в обсуждении команды, — субъективный прогноз ассистента. В задании нет правила «нет lock-файла = минус два балла». Окончательную оценку ставит жюри. Ниже — способы проверить конкретные свойства реализации.

## Один воспроизводимый отчёт

После установки по README выполните из корня проекта:

```bash
python scripts/check_release.py --output docs/check_local.txt
```

Скрипт сохраняет полный объединённый stdout/stderr каждой проверки, её код завершения и длительность. В отчёте есть UTC-время, ОС, Python, Git-коммит, список изменений отслеживаемых файлов, SHA256 исходного кода и данных, точные версии установленных пакетов. Переменные окружения и содержимое `.env` в отчёт не попадают. Повторный запуск требует нового имени файла: предыдущий отчёт не перезаписывается.

Проверки: `pip check`, `scripts/check_scenario.py`, полный `python -m pytest -q`. Для тестов дополнительно создаётся временный JUnit XML: PASS допускается только при ненулевом числе выполненных тестов, нуле ошибок, падений и пропусков. Сценарий должен завершиться с кодом 0 и результатом 11/11. При неполной проверке или ошибке итоговый код скрипта ненулевой.

LLM для проверки отключена через `AKIM_NO_LLM=1`; ключ не требуется. Этот отчёт проверяет локальную логику, а не доступность внешнего API, качество каждого ответа модели или Docker-сборку.

## Зависимости

`requirements.txt` остаётся основным набором допустимых версий для рекомендованного Python 3.11+ и Docker. Дополнительный `requirements-tested-windows-py310.txt` фиксирует все установленные runtime/test-пакеты контрольной машины Windows с CPython 3.10.9. Это снимок конкретного окружения, а не универсальный lock-файл с хэшами и не изменение рекомендованной версии Python.

Для воспроизведения именно дополнительной Windows-проверки на CPython 3.10.9 в новом виртуальном окружении:

```powershell
py -3.10 -m venv .venv-judge
.\.venv-judge\Scripts\python.exe -m pip install -r requirements.txt -c requirements-tested-windows-py310.txt
.\.venv-judge\Scripts\python.exe scripts/check_release.py --output docs/check_windows_py310.txt
```

Для другой ОС или версии Python устанавливайте основной `requirements.txt` и сохраняйте собственный отчёт. Окружения `.venv-*` исключены из Git и Docker-контекста.

## Независимая сверка расчётов

```bash
python -m pytest -q tests/test_calculation_audit.py
```

Тестовая эталонная функция отдельно реализует формулу задания через `Decimal`: эффекты с лагом, синергии, события, ограничение показателей 0–100, веса районов и штраф за критические показатели. Она не вызывает производственные функции применения эффектов и вычисления Score. Эталон использует тот же входной датасет; происхождение исходных данных подтверждается заданием и прежними тестами известных чисел.

Сравниваются три расчёта: независимый Decimal, обычный движок и векторный поиск NumPy. Проверяются лидеры, последний набор и фиксированная случайная выборка по пространству допустимых решений: 144 набора в 7 условиях, всего 1008 сравнений. Условия: базовый режим, четыре городских события, искусственный выход за границы 0/100, изменённые веса. Сравниваются Score и все пять районных индексов с абсолютной погрешностью не более `1e-10`; число критических показателей обычного движка должно совпасть точно. Отдельно пересчитываются все 50 сохранённых лидеров.

Это выборочная проверка согласованности двух реализаций, а не независимое доказательство оптимальности каждого из 694 395 наборов. Число допустимых наборов проверяется по построенному поисковому индексу. Полный повторный скалярный перебор остаётся отдельной, более долгой процедурой.

## Что остаётся проверить на финальной версии

- Основной README-путь на рекомендованном Python 3.11+ и Docker проверяет Claude на машине Виталия по командному расписанию; Windows 3.10 является дополнительным окружением.
- Живое качество AI-разбора и задержку на демонстрации нельзя доказать тестами с отключённой моделью.
- Значения из синтетического задания не подтверждают точность прогнозов для реальной Астаны.
- После нового коммита кода прежний отчёт подтверждает только указанную в нём версию. Для финальной сдачи нужен свежий запуск.
